# 주입 시나리오

재생 데이터에 의도적으로 품질 오염을 주입해, 검증 룰이 실제로 이상을
감지하는지 확인한다. 정의는 `config/scenarios.yml`.

## 설계 원칙
- 원본 parquet 은 변경하지 않는다. 이번 배치 사본에만 적용한다
- 시드를 날짜로 고정해 같은 날짜를 재실행하면 같은 결과가 나온다
- DB CHECK 제약을 위반하지 않도록 주입한다
  (금액을 비울 때 amount_flag 도 함께 채움)
- 지정 날짜가 아닌 날은 원본 그대로이므로 기준선이 유지된다

## 기준선 (2026-09-28 ~ 10-04, 7일)
| 룰 | 대상 | 범위 |
|---|---|---|
| X01 | orders.customer_id | 5~10건 (1.2~2.4%) |
| X03 | support_tickets.customer_id | 0~3건 |
| X04 | clickstream.customer_id | 57~79건 (1.0~1.4%) |
| D01 | orders.order_amount | 13~19% (기준 17.2%) |
| D05 | clickstream | 5,390~5,520행 (기준 5,400) |

## 시나리오 01 — 정규화되지 않은 범주값 유입
- **날짜**: 2026-10-05
- **내용**: `orders.payment_method` 3건을 `bitcoin` 으로 변경
- **배경**: 원본 정제 시 결제수단을 표준 4종으로 통일했으나,
  상류 시스템에서 비표준 값이 다시 유입되는 상황
- **기대**: D02 발동 (평소 0건)
- **결과**: ✅
  - `FAIL D02 orders.payment_method — new_values=1`
  - 격리 10건 (평상시 7건 + 주입 3건)
  - 적재 정상 완료 (370행)
- **설계 검증**: D02 를 경고가 아닌 **격리** 룰로 둔 것이 유효했다.
  경고로만 두었다면 `ck_orders_payment` CHECK 제약에 걸려
  배치 전체가 실패했을 것이다
- **증거**: `docs/evidence/scenario_01_category.txt`

## 시나리오 02 — 결측률 급증
- **날짜**: 2026-10-06
- **내용**: `orders.order_amount` 의 20%를 추가로 NULL 처리,
  `amount_flag` 에 `주입_상류결측` 기록
- **기대**: D01 발동 (기준 17.2%, 임계 ±10%p)
- **결과**: ✅
  - `WARN D01 orders.order_amount — null_rate=0.3396 (기준 0.172)`
  - 기존 17% + 주입 17% = 34.0%
- **부수 효과 (중요)**: KPI 에도 영향이 나타났다
  - GMV 모수: 82% → **65.5%**
  - AOV: 50,100 → **64,671** (결측이 무작위로 발생해 남은 표본의 평균이 이동)
  - → **"모수가 줄면 지표의 신뢰도가 떨어진다"** 를 수치로 확인.
    daily_kpi 에 order_null_rate 를 함께 기록한 설계가 여기서 작동했다
- **증거**: `docs/evidence/scenario_02_nullrate.txt`

## 시나리오 03 — 상류 수집 장애
- **날짜**: 2026-10-07
- **내용**: `clickstream` 적재량을 10%로 축소 (5,543 → 554행)
- **기대**: D05 발동
- **결과**: ✅
  - `WARN D05 clickstream — row_count=554 (기준 5400)`
  - KPI 이벤트 수 5,400 → 544
- **부수 효과 (중요)**: X04 고아행이 77 → **10건으로 감소**
  - 전체가 90% 줄었으니 고아행도 비례 감소
  - → **절대 건수만 보면 "품질이 개선됐다"고 오판할 수 있다.**
    품질 지표는 비율 기준이 함께 필요하다는 근거
- **증거**: `docs/evidence/scenario_03_shrink.txt`

## 확장 과제 (미구현)
- **시나리오 04 — FK 고아행 대량 유입**: 존재하지 않는 customer_id 200건 주입.
  X01 기준선(5~10건) 대비 20배. D08 격리율도 함께 발동 예상
- **상품 마스터 오염**: category 를 정규화 이전 형태로 되돌림.
  product_catalog 를 증분 공급하지 않기로 한 결정(C1) 때문에 미구현
- **시각 표기 오염**: event_time 을 UTC↔KST 로 뒤바꿈. R15 룰 신설 필요
